## What is callable

There is exactly ONE callable API in this record, and it is operated by the regulator.

- [DROP Data Broker API](https://privacy.ca.gov/drop-for-data-brokers/technical-specifications/):
  Base https://api.drop.privacy.ca.gov (sandbox https://api.drop.privacy.ca.gov/sandbox).
  OpenAPI 3.1.0, spec version 1.2.0, three operations. Auth: X-API-KEY header. Access
  requires registration as a California data broker plus a $6,000 annual fee — there is no
  self-service signup and no free tier.
- [OpenAPI specification](https://dropresources.blob.core.windows.net/apidocs/databroker_api.yaml):
  the first-party OpenAPI, linked from the CalPrivacy technical specifications page.

### Operations

- `GET /data/download` (`downloadData`) — request or download the ZIP archive of consumer
  deletion request data. 200 application/zip when ready; 202 + Retry-After while preparing;
  200 application/json when there is nothing new; 409 if a previous download is incomplete.
- `POST /data/upload` (`uploadData`) — upload CSV status response files. multipart/form-data,
  field name `files`, CSV header exactly `Id,Status`, Status one of 2/3/4/5.
- `POST /data/amend` (`uploadAmend`) — correct or update previously submitted status responses.

### Status codes reported per work item

- `2` Exempted — match found, all personal information is exempt
- `3` Deleted — match found, non-exempt personal information was deleted
- `4` Opted out — multiple consumers linked to one identifier, all opted out of sale/sharing
- `5` Not found — no match found after completing the matching process

### Things an agent must know before calling

- Consumer identifiers are never in the clear. Every identifier is SHA-256 hashed with UTF-8
  input and Base64 output, over CalPrivacy's published standardization rules. NDZ and NameVIN
  use composite hashing.
- There is NO idempotency mechanism. A retried upload is a new upload. Concurrency is
  constrained by 409 state gates, not by a key.
- `POST /data/amend` corrects the REPORT, not the underlying deletion. Status 3 asserts an
  irreversible real-world action. No amendment window is published — do not assume one.
- Rate limits are undocumented. Exhaustion is a 429 with the published guidance "wait 30
  seconds and retry". No X-RateLimit-* headers exist.
- Errors are not RFC 9457. 401 returns plain text; everything else returns hand-rolled JSON.
- A 202 upload response can still contain rejected files — read `rejected[]`, not just the code.

## Events

CalPrivacy publishes a webhook surface but no AsyncAPI. Five webhook event types
(`download.ready`, `upload.received`, `upload.processed`, `amendment.received`,
`amendment.processed`) plus two email-only notifications (API Key Issued, API Key Changed).
Deliveries are signed HMAC-SHA256 over `<timestamp>.<raw body>` in `X-Webhook-Signature`.
The body carries only `{"message": "..."}` — switch on `X-Webhook-Event-Type`, not the body.
